## Как пользоваться

В документе остаётся только то, что ещё не сделано. Внесённое собрано в таблице «Уже внесено» ниже. Значения можно вносить прямо в код (`src/content/site.ts`, `src/content/legal.ts`, `src/app/privacy/page.tsx`, `src/app/consent/page.tsx`, `.env`) или вписать сюда и вернуть файл: тогда внесу я, пересоберу сайт и проверю, что заглушек не осталось.

**Пароли и ключи (SMTP, секрет вебхука) сюда не вписывайте.** Они живут только в `.env` на сервере.

Публиковать с заглушками нельзя, поэтому `npm run build` с ними не соберётся: он напечатает, что осталось, и остановится. На 30.10.2026 защита проходит: заглушек, пустых реквизитов и адресов localhost нет. Проверка по коду:

```bash
NEXT_PUBLIC_SITE_URL=https://24trust.ru npm run build
```

Сборка проходит и пишет «Проверка заглушек пройдена». Без `NEXT_PUBLIC_SITE_URL` защита остановит сборку на адресе `localhost`: на сервере он задаётся в `.env` (инструкция по деплою, шаг 6). Посмотреть список, не останавливая сборку: `ALLOW_PLACEHOLDERS=1 npm run build`. Защита ловит только заглушки в скобках, пустые и нерабочие реквизиты и адрес сайта: ошибки в самих формулировках юридических текстов она не видит (см. часть 2.2).

### 2.2. Тексты политики и согласия: проверить формулировки

Защита сборки видит только заглушки в скобках, а не смысл и опечатки, поэтому тексты нужно вычитать глазами. Лишние «;» после ссылки на хостинг в политике п. 3.4 и в согласии п. 5 убраны 30.10.2026. Что видно сейчас (`src/app/privacy/page.tsx`, `src/app/consent/page.tsx`):

- вместо наименования и адреса хостинг-провайдера стоит только ссылка. Согласие по ч. 4 ст. 9 152-ФЗ должно называть лицо, которому поручена обработка, по наименованию и адресу, поэтому формулировку лучше показать юристу;
- строки про CRM или почтовый сервис нет. Это верно, пока заявки идут только в файл на сервере. Если подключите вебхук в CRM или почту по SMTP (часть 5.2), добавьте этого обработчика в оба текста;
- в согласии п. 7 между словом «e-mail» и адресом нет пробела: на странице выходит «e-mailinfo@24trust.ru». Адрес там вписан строкой, а не берётся из `company.dpoEmail`, как в политике, поэтому при смене адреса согласие придётся править отдельно;
- ссылки между политикой и согласием сделаны абсолютными (`https://24trust.ru/...`): пока сайт не опубликован, они ведут на внешний адрес, а не на страницу локального сайта.

Яндекс Метрика (ООО «ЯНДЕКС») указана в политике. Если Метрику не ставим, строки о ней нужно убрать из политики (п. 2.1, 3.4, 5.2) и из текста баннера cookie.

## 5. Домен, хостинг, заявки, Метрика

### 5.1. Домен и сервер

Домен внесён (`company.domain`). Осталось:

| Поле | Значение | Куда попадает |
| --- | --- | --- |
| Основной вариант: без `www` (как в `company.domain`) или с `www` | | nginx: второй вариант редиректит на основной |
| Хостинг в РФ (провайдер, тариф). Рекомендация: 1 vCPU, 2 ГБ RAM, 30 ГБ NVMe, Ubuntu 24.04 LTS, постоянный IPv4, плюс swap 2 ГБ для сборки | | часть 2.2 |
| IP сервера | | DNS: A-записи для `@` и `www` |

Адрес сайта задаётся при сборке: в `.env` на сервере `NEXT_PUBLIC_SITE_URL=https://24trust.ru`, с `https://`, без слеша на конце. Он попадает в canonical, sitemap, robots, Open Graph и в ссылку на согласие, которая сохраняется с каждой заявкой. Пока он не задан, сборка остановится. Значение и `company.domain` должны совпадать: если основной вариант с `www`, поменяйте оба. Если домен изменится, сайт придётся пересобрать.

В продакшене отдаётся HSTS с `includeSubDomains`. Если на поддоменах этого домена будет что-то по http, оно перестанет открываться. Если поддомены планируются, скажите, уберу этот параметр.

### 5.2. Куда уходят заявки

Работает любой набор каналов. Заявка принята, если сработал хотя бы один. Зарубежные сервисы (Gmail, Telegram-боты, Google Forms) не подключаем: ПДн граждан РФ записываются только в базы на территории РФ (ч. 5 ст. 18 152-ФЗ).

| Канал | Включить | Что нужно |
| --- | --- | --- |
| Файл `data/leads.jsonl` на сервере (включён по умолчанию) | да / нет | том с бэкапом, доступ только у ответственных |
| Вебхук в CRM или n8n (`LEAD_WEBHOOK_URL`) | да / нет | URL: ______ · секрет — только в `.env` |
| Письмо через SMTP (`SMTP_*`, `LEAD_NOTIFY_TO`) | да / нет | см. ниже |

Если оставить только файл, о новой заявке никто не узнает, пока не заглянет на сервер. Лучше включить почту или вебхук.

Для письма:

| Поле | Значение |
| --- | --- |
| SMTP-сервис | например, Яндекс 360: `smtp.yandex.ru`, порт 465 |
| Логин (`SMTP_USER`) | |
| Адрес отправителя (`SMTP_FROM`) | лучше на своём домене, иначе письма чаще попадают в спам |
| Кому слать уведомления (`LEAD_NOTIFY_TO`) | |
| Пароль (`SMTP_PASS`) | не сюда, сразу в `.env` на сервере |
