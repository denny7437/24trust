# TrustGuard AI — сайт

Посадочная страница TrustGuard AI с формой заявки на пилот, страницы `/privacy` и `/consent`, баннер cookie. Вёрстка по макету на канвасе «TrustGuard AI — три направления главной» (артборды «Главная · часть 1/2», «Мобильная · 1–3», «Мобильная · меню», «Логотип A») и по документу «Структура и тексты блоков» от 26.10.2026.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · CSS Modules · шрифты Onest и Unbounded с собственного сервера (`@fontsource`) · nodemailer — только если включены письма о заявках.

## Запуск

Нужен Node.js 20.9 или новее (лучше 22 LTS).

```bash
npm install
cp .env.example .env.local      # заполнить NEXT_PUBLIC_SITE_URL, остальное — по желанию
npm run dev                     # http://localhost:3000
```

Продакшен-сборка:

```bash
npm run build
npm start
```

Сборка останавливается, пока на сайте остались `[заглушки]`, пустые реквизиты или адрес сайта `localhost`: после `next build` сам запускается `scripts/check-placeholders.mjs` (хук `postbuild`), печатает, что осталось, с файлами и строками, и завершается с кодом 1. Для проверки черновика на своей машине: `ALLOW_PLACEHOLDERS=1 npm run build` или строка `ALLOW_PLACEHOLDERS=1` в `.env.local`. Проверка тогда только предупреждает. На сервере и в боевой сборке эту переменную не задавайте. Проверка не заменяет вычитку: верны ли цифры реквизитов, она не знает, заглушку, которая есть только в коде компонента, не увидит, а `next build` напрямую её обходит.

Проверки: `npm run lint`, `npm run typecheck`, `npm run check:placeholders` (заново прогоняет проверку заглушек по последней сборке, без пересборки).

`package-lock.json` лежит в репозитории: образ ставит зависимости через `npm ci` строго по нему, поэтому сборки воспроизводимы. Меняйте его только через `npm install` и коммитьте вместе с `package.json`.

## Анимации

Появление первого экрана, плавающий щит и карточки, пульсирующая точка «Набираем первые пилотные компании», бегущие пунктиры на схеме, блик на основных кнопках, подъём карточек при наведении, поворот иконок, плюс → крестик в вопросах, подсветка строки таблицы, «опускание» щита в логотипе. Блоки проявляются при прокрутке там, где браузер поддерживает scroll-driven animations; в остальных браузерах они просто видны. При «Уменьшить движение» в системе анимации отключаются.

## Форма и заявки

Поля, подсказки и тексты ошибок — по документу. «Обсудить пилот» и «Подать заявку на пилот» выбирают тему «Пилот», «Задать вопрос» — тему «Другое». Если форма уже на экране (справа), страница не прокручивается: форма подсвечивается, курсор встаёт в поле «Имя».

`POST /api/lead` проверяет поля так же, как браузер, и ещё:

- не сохраняет заявку, если заполнено скрытое поле-ловушка;
- пускает не больше 5 запросов за 10 минут с одного IP (в памяти процесса — для нескольких реплик используйте `limit_req` в nginx);
- отклоняет запросы с чужим `Origin` и телом больше 20 КБ.

Куда уходят заявки (включается переменными окружения, работает любой набор):

1. **Файл** `data/leads.jsonl` на своём сервере — включён по умолчанию (`LEADS_DIR`, `LEADS_FILE=off` — выключить).
2. **Вебхук** в CRM или n8n на российских серверах — `LEAD_WEBHOOK_URL` (+ `LEAD_WEBHOOK_SECRET`).
3. **Письмо** через SMTP российского почтового сервиса — `SMTP_*` и `LEAD_NOTIFY_TO`.

Заявка считается принятой, если сработал хотя бы один канал. Не подключайте Gmail, Google Forms, Telegram-ботов и другие зарубежные сервисы: персональные данные граждан РФ записываются только в базы на территории РФ (ч. 5 ст. 18 152-ФЗ).

**Доказательство согласия** (ч. 3 ст. 9 152-ФЗ) сохраняется в каждой заявке, в поле `consent`: дата и время, IP, User-Agent, адрес страницы, текст чекбокса, версия и ссылка на документ согласия. Правите текст согласия — поднимите `consentDoc.version` в `src/content/legal.ts`.

`npm run leads:csv` выгружает заявки в `data/leads.csv` для Excel. `npm run leads:purge` удаляет заявки старше 3 лет — это срок из Политики; поставьте команду в cron раз в сутки. Папка `data/` в git не попадает.

## Cookie и Яндекс Метрика

- `NEXT_PUBLIC_YM_ID` задан: баннер «Принять все / Только необходимые». Метрика загружается только после «Принять все». При отзыве согласия её cookie удаляются, страница перезагружается без счётчика.
- `NEXT_PUBLIC_YM_ID` пустой: аналитика выключена, баннер — короткое уведомление о необходимых cookie с кнопкой «Понятно».
- Выбор хранится 12 месяцев в cookie `tg_cookie_choice`. Ссылка «Настройки cookie» в подвале снова открывает баннер.
- Вебвизор выключен.
- Цели Метрики (тип «JavaScript-событие»): `pilot_cta_click` — клики «Обсудить пилот» и «Подать заявку на пилот»; `question_cta_click` — «Задать вопрос»; `lead_form_submit` — заявка отправлена.

`NEXT_PUBLIC_*` подставляются при сборке: после их изменения пересоберите проект.

## Безопасность

В продакшене отдаются заголовки: Content-Security-Policy (свой домен + Яндекс Метрика), `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS (`next.config.ts`). Шрифты и скрипты — только со своего домена. Заголовок `X-Powered-By` выключен.

## Деплой

Репозиторий: `git@github.com:denny7437/24trust.git` (приватный, ветка `main`). Хостинг — в РФ (например, Yandex Cloud, Selectel, VK Cloud, Timeweb Cloud). Сборка `output: 'standalone'`, есть `Dockerfile` и `docker-compose.yml`.

Полная пошаговая инструкция (SSH, Docker, nginx, сертификат Let's Encrypt, обновление, откат, бэкап, разбор ошибок) лежит в корне репозитория: `{strategy} {guide} TrustGuard сайт, деплой на сервер – 2026-10-30.md`. Коротко, на сервере:

```bash
git clone git@github.com:denny7437/24trust.git /opt/trustguard-site   # для приватного репозитория нужен deploy key, см. инструкцию
cd /opt/trustguard-site
cp .env.example .env            # заполнить, обязательно NEXT_PUBLIC_SITE_URL=https://ваш-домен
mkdir -p data && chown 1001:1001 data && chmod 700 data   # пользователь внутри контейнера — uid 1001
docker compose up -d --build    # приложение слушает 127.0.0.1:3000
```

Обновление: `git pull --ff-only && docker compose up -d --build`. Образ собирается через `npm run build`, поэтому с заглушками сборка остановится (см. «Запуск»). Черновик для проверки: `ALLOW_PLACEHOLDERS=1 docker compose up -d --build`. Для боевого сайта переменную не задавайте.

Перед приложением нужен nginx с HTTPS. Проверенный конфиг (редирект с http и с `www`, сертификат Let's Encrypt, лимит заявок с ответом 429) приведён в инструкции, шаги 8–10. IP посетителя для лимита и доказательства согласия берётся из `X-Real-IP` / `X-Forwarded-For`, поэтому Node-сервер не должен быть доступен из интернета напрямую. Телеметрия Next.js в Docker выключена (`NEXT_TELEMETRY_DISABLED=1`).

## Открытые вопросы

- **Демо.** Блок «Проверьте, как фильтр оценит текст» убран по решению от 26.10.2026. Цель гранта — «презентационный сайт с демо», поэтому вернуть демо можно отдельным блоком или страницей `/demo`, когда юрист утвердит примеры. Вместе с демо в Политику нужно вернуть пункт о текстах демо и цель «ограничивать число проверок в демо».
- **Карточка «Юридический риск»** упоминает составы КоАП и УК РФ, а правило документа — ссылаться только на сверенные нормы (ст. 10.6 ФЗ-149). Сверить с юристом.
- **Реплики на первом экране** взяты из набора примеров для демо — их утверждает юрист.
- **Строка о 243-ФЗ** — сверить с разбором LKB-001.
- **Строка о команде** (OSMI AI, НИУ ВШЭ) не выводится, пока нет решения: `about.team` в `site.ts`.
- **Перефраз на жёлтом вердикте** и лимит «одна попытка» — подтвердить готовность (задача в Backlog).
- **Плагин** показан «в разработке»; если до юрпроверки по РИД его не показываем — убрать колонку в `delivery`.
- **Заголовок первого экрана** — основной вариант; альтернативы в документе.
- **Логотип** — применён вариант A, варианты B и C — на канвасе.
